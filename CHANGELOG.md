# Changelog

## 2.0.0

A rewrite of Epitope-Evaluator. The six tools, their parameters and their
scientific purpose are unchanged; the parsing, the analysis engine, the figures
and the error handling are new.

---

## Repository layout

Two directories keep the paths they were published under, because this
repository is cited and external links to them should not break:

- `Biological_Applications_Data/` — the datasets behind the 2022 paper. The app
  now reads its examples directly from here rather than keeping a second copy.
- `Images/` — the 13 figures the v1 README embedded by absolute GitHub URL.
  Nothing in v2 references them; they are retained only so those links resolve.

Removed: `modules/example/` (2,149 lines duplicating the seven modules with an
`e_` prefix), `data/example.xls` (byte-identical to `example_NetMHCPAN.xls` and
referenced by nothing), and `Help Section.txt` (superseded by the in-app help
panels).

---

## Branding

- **The app has a mark.** It echoes the Epitope Viewer — a protein backbone with
  epitope blocks beneath it on the same yellow-to-red "alleles bound" ramp — so
  the icon and the figures come from one visual idea. It is generated by
  `tools/make_icons.R` from the palette in `utils/constants.R`, which is what
  stops the branding and the plots drifting apart.
- **Favicon**: `favicon.svg` for browsers that take SVG, `favicon-32.png` for
  those that do not, `favicon-180.png` for iOS, plus a `theme-color` meta. The
  SVG declares an intrinsic `width`/`height` as well as a `viewBox` — without
  one Firefox reports `naturalWidth` 0 and some contexts fail to size it.
- **Navbar**: the mark sits on a light plate beside the wordmark, because its
  own navy background would otherwise vanish into the navy bar. The wordmark
  drops below 576 px and the mark stays.
- `deploy.R` now bundles `www/*.{svg,png,ico}` — previously only `.css` was
  picked up from the top of `www/`, so the icons would have deployed as 404s.
  Its pre-flight guard was extended to check every `href`/`src` the app
  references, not just the example datasets.

## Content and packaging (post-deployment review)

- **The paper's own datasets are now bundled.** `data/biological/` carries the
  SARS-CoV-2 class I and class II predictions and the six Spike variants from
  Soto et al. 2022. The example dropdown is grouped into "One predictor per
  format" and "Biological applications", each entry with a one-line note. The
  Spike set is the case the Conservation tool exists for: 277 epitopes shared
  by all six variants, and Omicron carrying by far the most private ones.
- **Dotted allele names are canonicalised.** v1 rewrote `:` and `-` as `.` so
  names were valid data.frame columns, and every table it exported carries that
  form. `HLA.A01.01` now becomes `HLA-A01:01` and `DRB1.03.01` becomes
  `DRB1_0301`, but only for unambiguous fully-dotted patterns; anything else is
  left exactly as the file spelled it. **This also fixed MHC-class detection**,
  which returned "unknown" for the paper's own class I table -- found by testing
  against a real file rather than the bundled demos.
- **MHC class is detected across naming conventions**: `HLA-A01:01`,
  `HLA.A01.01`, `HLA_A0101`, `HLA-A*02:01`, `HLA A01:01`, `H-2Kb`, `DRB1.03.01`.
- **Documentation shows the real files again.** Each predictor panel now renders
  the first rows of the bundled example as a table -- with the NetMHC family's
  two header rows shown *as* header rows, since that structure is the single
  most confusing thing about the format -- alongside paper, version, site and
  the columns actually read. v1 did this with a live `renderDataTable`; here it
  is static HTML built at UI time, so there is no per-session round trip.
- **`bsicons` removed.** It was referenced behind `requireNamespace()` but is
  not installed, so every deployment logged a missing-package warning while
  contributing nothing.
- **`deploy.R` lists `data/` recursively** and refuses to build a bundle whose
  `EE_EXAMPLES` entries are not all included -- otherwise the biological
  datasets would have deployed as broken links.
- **`setDTthreads()` no longer crashes on startup in a container.**
  `parallel::detectCores(logical = FALSE)` returns `NA` on shinyapps.io, and
  `min(2L, NA)` is `NA`, which `setDTthreads()` rejects with an error. The app
  would not have booted there.
- **`data/example.xls` deleted**: byte-identical to `example_NetMHCPAN.xls` and
  referenced by nothing, 6.3 MB of dead weight in every upload.

## Interface fixes (post-review)

Found by driving the running app in a browser rather than only building it.

- **Hover tooltips showed `customdata[0]` as literal text.** plotly silently
  drops a `customdata` matrix on several trace types during R→JSON
  serialisation, so every `%{customdata[N]}` reference rendered as source text.
  All hover text is now pre-formatted into `hovertext`/`text`, and
  `tests/test_app.R` asserts that every `%{field}` a hovertemplate references
  actually exists on the built trace with one entry per point.
- **Run-button behaviour was inconsistent between tools.** There is now one
  rule everywhere: parameters that define the analysis (alleles, proteins,
  cutoffs, AND/OR) sit above the Run button and take effect only when it is
  pressed; presentation options (plot type, sort order, log scale, labels) sit
  below it under a **DISPLAY** heading and apply immediately. Every tool also
  computes once when a dataset loads, so a tab is never blank on arrival.
- **The page scrolled inside a nested container.** bslib's fill layout made the
  results column a viewport-height flexbox with its own scrollbar, so content
  above the fold was lost. Tool pages now use ordinary document flow, the
  window is the only scroller, the navbar is sticky, and the parameter sidebar
  is sticky so it stays beside the results.
- **Static pages stretched to equal-height grid cells**, leaving ~400 px of
  dead space under the shorter card of a side-by-side pair.
- **Intersection and Conservation tables pasted thousands of peptide sequences
  into one cell**, making single rows thousands of pixels tall (the Intersection
  page was 4,471 px). The screen table now shows the first six and `(+N more)`;
  the download still contains every sequence.
- **The UpSet set-size axis showed negative labels** (−400, −200) because the
  bars are mirrored to grow leftwards.
- **The Density colourbar showed raw log₁₀ values** (0–2.5) under a "Number of
  epitopes" title: `ticktext` needs `tickmode = "array"`, and the label vector
  was being collapsed to length 1 by an `ifelse()` on a scalar condition. It now
  reads real counts (0, 2, 9, 31, 99, 315).
- **Promiscuity opened on an empty heatmap.** The inherited default of
  (alleles − 1) means 11 of 12, which nothing satisfies at 2 %rank. The minimum
  is now derived from the data: the strictest threshold still leaving at least
  25 epitopes. On the class I example that is 6 alleles / 34 epitopes instead
  of 11 / none.
- **About, Documentation and Tutorial had no figures.** They now carry nine
  screenshots of this build, captured by `tools/screenshots.py`, each linking to
  the live view it shows. Re-run that script after any layout change; a test
  asserts every referenced image exists.
- **Deep links** were added: `?page=Run+example&tool=Viewer` opens straight at
  that view, which is what makes the screenshot pipeline reproducible.

## Behavioural changes — results that differ from v1

These change numbers relative to the version used in the 2022 paper. Each is a
correction; the reason is given so a published figure can be reconciled.

### 1. Protein length is the true amino-acid length

All five v1 parsers computed protein length as `nchar(sequence) - 8`
([`utils/parsing_functions.R:55`](https://github.com/SotoLF/Epitope-Evaluator/blob/main/utils/parsing_functions.R#L55)
and equivalents), then labelled it "protein length in amino acids" in the
Density tool and used it as the denominator of every density value.

- SARS-CoV-2 Spike is 1273 aa; v1 reported 1265.
- `L - 8` is the number of 9-mer windows, so it was not even a correct window
  count for class II: a 15-mer sliding window over 1273 residues gives 1259.

v2 takes the length from the FASTA. **Epitope densities are therefore lower
than v1's by a factor of `(L-8)/L`** — about 0.6 % for Spike, 27 % for a 30 aa
peptide, and undefined (negative) in v1 for any protein shorter than 8 aa.

### 2. Promiscuity counts alleles with `<=`, not `<`

v1's table counted binders with `rowSums(scores < weak_cutoff)`
([`modules/promiscuity.R:118`](https://github.com/SotoLF/Epitope-Evaluator/blob/main/modules/promiscuity.R#L118))
while the heatmap beside it classified with `<=`. The two disagreed for every
epitope whose score sat exactly on the cutoff. v2 uses `<=` throughout, matching
the documentation. Epitope counts at round cutoffs may be marginally higher.

### 3. NetMHCpan / NetMHCIIpan "Score" reads the right column

For files exported without the `-BA` block, v1 selected score columns with
`seq(from = 7, by = 3, ...)` where the block stride is 4. The resulting indices
landed on `icore` — a peptide string — which `as.numeric()` turned into `NA`.
Selecting "Score" on such a file produced an all-`NA` analysis with no warning.

v2 locates the score column by name inside each allele's block, derived from the
file's own two-row header, so it is correct for any stride and any NetMHC
version. **Anything previously run as NetMHCpan/NetMHCIIpan + "Score" should be
re-run.**

### 4. Protein identifiers are matched by name, not by position

v1 mapped prediction-file protein IDs onto FASTA records by taking
`unique(results[, 3])` and lining it up positionally against the FASTA order
([`utils/parsing_functions.R:63`](https://github.com/SotoLF/Epitope-Evaluator/blob/main/utils/parsing_functions.R#L63)).
Any protein too short to yield a single peptide never appears in the prediction
file, so the vectors fall out of step and **every subsequent protein gets the
wrong identifier and the wrong length** — silently.

v2 matches by name (exact, then truncation-aware prefix against several
identifier variants, then by the protein length the prediction file implies) and
reports which strategy it used. A positional fallback is still available but
only when nothing matched by name, and it says so.

### 5. Missing scores are missing, not zero

MHCflurry and IEDB do not score every peptide against every allele. v1 let those
`NA`s reach `min()`/`max()` without `na.rm`, so a single unscored allele turned
the whole peptide's combined score into `NA` and dropped it from the analysis.
v2 excludes `NA` from the combination and treats it as "not a binder", never as
a score of zero. **MHCflurry and IEDB analyses will find more epitopes.**

### 6. Allele names keep their punctuation

v1 rewrote `:` and `-` as `.` so allele names were valid data.frame column names
(`HLA-A01:01` → `HLA.A01.01`), and that mangled form appeared in every plot,
table and download. v2 stores scores in a matrix, so the original names survive.

### 7. Distribution bins are half-open with a closed upper edge

Bins are `[lo, hi)` except the last, which is `[lo, hi]`, so a peptide scoring
exactly the maximum is counted. Boundary counts may shift by a few peptides.

## Defects fixed (no change to correct results)

- **UpSet plots did not render at all on current R.** `get_intersect_members()`
  called `dplyr::filter_()`, defunct since dplyr 1.1. Both the Intersection and
  Conservation UpSet plots crashed.
- **Input validation crashed on every multi-FASTA.**
  `if (is.na(tryCatch(read.fasta(...))))` evaluates `if` on a length-*n* logical,
  an error since R 4.2.
- **Class-aware defaults never applied.** `data_input.R` called
  `updateNumericInput()` on the data-input module's own session, so the ids
  resolved to `data_input-cutoff` instead of `distribution-cutoff`. All eight
  updates were no-ops, and class II users always got class I cutoffs.
- **The Density scatter broke when a row was selected.** The highlighted trace
  used `as.factor(Length)`/`as.factor(count)` while the base trace was numeric;
  mixing categorical and continuous data on one plotly axis mangles the scale.
- **The Tutorial tab showed eight broken video players.** `www/videos/*.mp4` is
  gitignored and absent from the repository. v2 checks for each file and falls
  back to the written walkthrough.
- **Every parser ran twice per load** — once inside `validate(need(...))` and
  once for the result.
- **Errors produced grey panels or a disconnected session.** Every output is now
  wrapped so a failure shows the actual message in place and the session lives.
- Package conflicts: `reshape` and `reshape2` were both attached (both archived
  on CRAN), with `reshape::rename` masking `dplyr::rename`.

## Performance

Measured with `tests/benchmark.R` on a synthetic 731 MB NetMHCpan table —
1,000,000 peptides × 20 alleles × 400 proteins — on one core.

| Step | v2 | v1 approach |
|---|---|---|
| Parse the 731 MB file | **4.0 s** | 24 s before column selection was added |
| Combine 20 alleles (AND/OR) | 0.17 s | `apply()` over a data.frame |
| Histogram, 200 bins | 0.04 s | all 10⁶ values shipped to the browser |
| Allele × cutoff grid (20 × 40) | 1.5 s | 6.1 s |
| UpSet over 20 alleles | 1.2 s | 1,048,575 full-table `filter_()` calls (and defunct) |
| Protein × allele grid (400 × 20) | 0.3 s | 1.2 s via `melt()` to 20 M long rows |
| Viewer lane packing, 800 epitopes | **0.004 s** | **119 s** |
| Promiscuity over 20 alleles | 0.3 s | — |
| **All six tools after parsing** | **8.0 s** | — |

The Viewer is the largest single win: v1's pairwise overlap search is why that
tool was documented as taking "a few minutes". v2 uses a first-fit interval
sweep, which is also optimal in the number of rows it produces.

Memory: the parsed object is 321 MB at that scale and the heaviest tool adds
~360 MB of transients, so 10⁶ peptides × 20 alleles wants roughly 1 GB. The
default shinyapps.io container is tight for that; a 300 MB input (~400 k
peptides) fits comfortably. The bundled SARS-CoV-2 examples use well under
100 MB.

Now: `shiny`, `bslib`, `plotly`, `DT`, `data.table`, `matrixStats`, `stringi`.

| Removed | Why |
|---|---|
| `ggVennDiagram`, `sf` | `sf` needs GDAL/GEOS/PROJ on the host — the most likely cause of a failed deploy. The Venn diagram is now drawn with plotly shapes. |

| `reshape`, `reshape2` | Archived on CRAN. Replaced by `data.table`. |

## Structure

`modules/example/` is gone. v1 duplicated all seven modules there — 2,149 lines
of copy-paste with an `e_` prefix on every input id. Shiny modules are already
namespaced, so one module set now serves both the Analyse tab and the Run
Example tab. Total R code: 5,923 lines → about 3,400, including two test suites
that v1 did not have.

The analysis engine (`utils/core_functions.R`, `utils/parsing_functions.R`) is
pure R with no Shiny dependency, so `tests/test_core.R` runs without Shiny
installed and the functions are usable directly from a script.

## New

- **Format auto-detection.** The predictor is identified from the file header
  and pre-selected; the choice can still be overridden.
- **Loading notes.** Anything unusual about the input — IDs resolved by prefix
  matching, alleles dropped for having no numeric values, a FASTA whose lengths
  disagree with the prediction, rows dropped as incomplete — is reported rather
  than absorbed.
- **Summary strip** above every tool: how many epitopes the current parameters
  select, before reading the figure.
- **Render guards.** Heatmaps, UpSet bars and Viewer rectangles are capped, with
  a note saying so. Downloads are never capped.
- **Colourblind-safe palette** (Okabe-Ito derived) used consistently.
- **PNG export at 1600×1000, 2× scale** instead of screen resolution.
- **Two test suites** — `tests/test_core.R` (155 assertions, no Shiny required)
  and `tests/test_app.R` (226 assertions, drives every module server with
  `shiny::testServer`, checks hover fields survive serialisation, and verifies
  every documentation image resolves) — plus `tests/benchmark.R` and
  `tools/screenshots.py`.
